# Idea: Preserve Experiment Artifacts

## Status

Proposed. Inventory and migration are explicitly delegated to the other working
session. This discussion fork must not perform the migration.

## Motivation

Much of the exploratory work was placed under `/tmp/opencode`. Temporary storage
is easy to lose and makes exact experiments difficult to rerun, audit, or compare
with later variants. Conclusions in `docs/research-notes.md` are useful, but some
need executable scripts and machine-readable records behind them.

## Known temporary material

`/tmp/opencode` contains experiment families for scale offsets, calibration
weighting, activation weighting, Q/K weighting and balancing, permutations,
Hadamard rotation and gating, SOAR-style refinement, prototype quantizers,
verification scripts, benchmark records, logs, duplicate solution snapshots,
exports, screenshots, and caches.

This is only a high-level observation, not a completed inventory.

## Proposed repository structure

The working session should first inspect existing conventions and then consider a
minimal structure such as:

```text
experiments/
  README.md
  linear/
  attention/
  common/
benchmarks/records/
```

Do not adopt this layout mechanically if the existing `tools/` and `benchmarks/`
structure already provides a cleaner home.

For each preserved experiment, retain:

- A small runnable script or documented command.
- Base Git tag/commit and candidate source identity.
- Dataset suite, seed, shape, and distribution/model provenance.
- Hyperparameters and policy thresholds.
- Machine-readable quality results.
- Runtime measurement and hardware/thread settings when relevant.
- A short conclusion including regressions and rejected cases.

Do not retain unless independently useful:

- `__pycache__` and generated bytecode.
- Duplicate submission ZIPs already reproducibly exported from Git tags.
- Duplicate copies of tagged `solution.py` files.
- Incidental browser output, screenshots, DOM dumps, or stale debug logs.
- Large records that can be reproduced cheaply and add no audit value.
- Secrets, credentials, model tokens, or copyrighted/restricted model artifacts.

## Migration process

1. Inventory temporary files by experiment family and identify entry points.
2. Map each family to conclusions already documented in
   `docs/research-notes.md` and `docs/variants.md`.
3. Determine which scripts still run against the current repository.
4. Promote only the smallest reproducible subset.
5. Replace hard-coded `/tmp` paths and undocumented dependencies.
6. Add a smoke test or explicit rerun command where practical.
7. Verify that promoted records agree with documented conclusions.
8. Commit migration separately from algorithm changes.

## Success criteria

Another session should be able to check out the repository, select a documented
experiment, run one command, and understand what hypothesis was tested and why
the result supported promotion or rejection.
